# CLAUDE.md

Working instructions for Claude Code sessions on this project. Read `README.md` for the full description
(task, data, training details, outputs); this file is about **how to work here safely**.

## Project in one paragraph

An image classifier for the 10 "Natural objects" classes of a task briefing: golden retriever, Labrador
retriever, Siberian husky, pug, sunflower, banana, orange, mushroom, butterfly, pine cone. The team owns only
these 10; the 10 man-made classes belong to another team, so never add them. Each model architecture has its own
notebook in `notebooks/`, generated by `scripts/create_notebook.py`; all notebooks call the shared package
`imgcls/`. Deliverables: a predictions CSV for a hidden test set (`filename, predicted category`), a 1–2 page
report (method, accuracy, three most common failure cases), and a 5-minute presentation.

## Environment

- Windows 11; shells: PowerShell (default) and Git Bash. Use forward slashes and quote paths: the project folder
  name contains a space (`D:\Image Classification`).
- Python 3.14.7 virtual environment in `.venv/`. Always run Python through it:
  `./.venv/Scripts/python.exe ...` (Jupyter: `./.venv/Scripts/jupyter.exe ...`).
- **This laptop has no NVIDIA GPU**, and the installed PyTorch is the CPU build (`2.15.0+cpu`). 8 logical cores,
  16 GB RAM. Training and CLIP scoring are slow here, and the user often runs notebooks at the same time, so don't
  start CPU-heavy jobs without asking. Run anything longer than ~2 minutes in the background.
- The C: drive is ~94% full. The Hugging Face model cache is at `C:\Users\Admin\.cache\huggingface\hub`. Don't
  download large models without saying so. Never delete cache folders other than ones this project created
  (`models--timm--*`, `models--laion--CLIP-*`); the `docling-*` and `sentence-transformers` entries belong to
  something else.
- Git: remote `origin` is `github.com/M0HiT27/Image-Classification`. The user pulls it on a second laptop that
  has an NVIDIA RTX 2050 (4 GB VRAM, Python 3.12, CUDA PyTorch from the `cu132` index). Commit or push only when
  the user asks. `data/`, `output/`, `*.pth`, `.venv/` are ignored.
- **Windows + CUDA PyTorch + DataLoader workers:** each worker process loads all of PyTorch, and several pools at
  once hung the GPU laptop (validation workers never started). `imgcls/data.py` therefore gives worker processes
  only to the training loader on Windows, and `imgcls/engine.py` falls back to single-process loading when workers
  time out (`LOADER_TIMEOUT`, default 180 s) or crash. Keep both behaviours; on that laptop `NUM_WORKERS = 2` is
  the sensible maximum. With 4 GB VRAM, `BATCH_SIZE = 16` may be needed for resnet50 and convnext_tiny.
- **Google Colab and Kaggle** run the same notebooks (README > "Colab and Kaggle"). The setup cell clones the
  public GitHub repo when it isn't inside the project, so cloud runs use the **pushed** `main`, not local edits.
  `imgcls.setup_environment()` (`imgcls/environment.py`) picks the folders: Colab unpacks
  `MyDrive/imgcls/imgcls_data.zip` to `/content/imgcls_data` and saves runs to `MyDrive/imgcls/output`; Kaggle
  finds the attached dataset under `/kaggle/input` and saves to `/kaggle/working/output`. `IMGCLS_DATA_DIR` /
  `IMGCLS_OUTPUT_DIR` override both. The zip is made by `scripts/pack_data.py` (`dist/`, git-ignored; re-run it
  after data changes). Code must stay Python 3.10-compatible for the cloud (no 3.12-only f-strings).
  Kaggle notebooks run on Colab's image (`google.colab` imports, `/content` exists, but Drive can't be mounted),
  so `detect()` must check for Kaggle before Colab.

## Hard rules

1. **`data/` is the only copy of the images.** The staging folders (`raw_data/`, `new_data/`, `rejected/`,
   `_downloads/`) were deleted on purpose, and `data/` is not in git. Never delete, move, rename or rewrite anything
   in `data/` without the user's explicit confirmation for that specific change.
2. **Never run `scripts/apply_screening.py --apply` for a class that is already in `data/`.** It rebuilds
   `data/<class>` from staging folders that no longer exist. A safeguard makes it print
   `SKIPPED: ... source files are gone`; never bypass it with `--allow-missing`.
3. **Keep the test split untouched during training.** The best epoch is chosen on a validation split carved out
   of `train/` (`VAL_FRACTION`). Don't add code that tunes thresholds, epochs or hyperparameters on `test/`.
4. **Put shared logic in `imgcls/`, not in notebooks.** Notebooks stay thin and are generated from the template.
   Create new model notebooks with `scripts/create_notebook.py`; never copy a notebook by hand.
   Use `--force` only when the user asks: it discards their edits.
5. **Keep the `imgcls` API used by the notebook template stable:** `setup_environment`, `set_seed`,
   `get_device`, `discover_classes`, `create_model`, `config_from_globals`, `build_data`, `train`,
   `evaluate_run`, `predict_folder`, `OUTPUT_DIR`. `DATA_DIR` / `OUTPUT_DIR` can change at run time
   (`setup_environment`, `use_paths`), so read them as `config.DATA_DIR` inside `imgcls/`, never as default arguments. If one must change, update the template in `scripts/create_notebook.py` and
   tell the user that existing notebooks need regenerating.
6. **Don't delete runs in `output/`** unless the user asks; each holds a `best.pth` that may be their best model.
7. **The user reviews images by hand and deletes bad ones.** Treat files that disappear as deliberate rejections;
   don't restore them.
8. **`data_object/` is derived from `data/`** (object detection notebook 01 rebuilds `images/` and `labels/`). Never
   write boxes, labels or resized copies into `data/`. Keep `data_object/_cache/` (the downloaded Open Images box
   rows and the OWLv2 results, hours of CPU time); don't delete it without asking.

## Common tasks

### Object detection notebooks

`object_detection_notebooks/` holds 01 (build `data_object/`), 02 (Ultralytics YOLO) and 03 (Faster R-CNN on our
MobileNetV3), generated by `scripts/create_detection_notebooks.py` from the same setup-cell pattern as the
classifier notebooks; the code is in `imgcls/objdet/`. Regenerate with `--force` only when the user asks.
Both detectors are scored by `imgcls/objdet/metrics.py` so their mAP compares. `ultralytics` is installed in the
venv with `--no-deps` (it requires `opencv-python`, which would clash with `opencv-python-headless`); its
pretrained weights go to `model_cache/ultralytics/`. Smoke test (then delete the `smoketest_*` notebooks,
`output/smoketest_*` and the scratch `data_object`):

```bash
./.venv/Scripts/python.exe scripts/create_detection_notebooks.py --only 01 --prefix smoketest_ --set LIMIT_PER_CLASS=4 --set "OBJECT_DIR='<scratch>/data_object_smoke'"
./.venv/Scripts/python.exe scripts/create_detection_notebooks.py --only 02 --prefix smoketest_ --set MODEL_NAME=smoketest_yolo --set EPOCHS=1 --set IMG_SIZE=320 --set "OBJECT_DIR='<scratch>/data_object_smoke'"
./.venv/Scripts/python.exe scripts/create_detection_notebooks.py --only 03 --prefix smoketest_ --set MODEL_NAME=smoketest_frcnn --set EPOCHS=1 --set IMG_SIZE=320 --set BATCH_SIZE=4 --set "OBJECT_DIR='<scratch>/data_object_smoke'"
```

Execute each with `jupyter nbconvert --execute` as for the classifier smoke test. 01 on CPU runs OWLv2 on about
40 photos (5-10 min) and, the first time, streams the Open Images box files (about 2.4 GB read, only our rows
kept); copy the scratch `_cache/openimages_*` into `data_object/_cache/` so a real build doesn't stream again.

### Add a model

```bash
./.venv/Scripts/python.exe scripts/create_notebook.py <name> --arch <timm model name> [--lr 1e-4] [--set KEY=VALUE ...]
```

- Check the architecture exists first:
  `./.venv/Scripts/python.exe -c "import timm; print(timm.list_models('*<pattern>*', pretrained=True))"`.
- Learning-rate guide used for the presets: small CNNs 1e-3, ResNet 5e-4, ConvNeXt 2e-4, ViT 1e-4.
- Permanent presets live in `PRESETS` in `scripts/create_notebook.py`.

### Smoke-test the training code after changing `imgcls/` or the template

Generate a throwaway notebook with tiny settings, execute it headless, check the run folder, then delete both:

```bash
./.venv/Scripts/python.exe scripts/create_notebook.py smoketest --arch mobilenetv3_large_100.ra_in1k --epochs 2 --batch-size 16 --set LIMIT_PER_CLASS=12 --set SAMPLES_PER_CLASS=8 --set NUM_WORKERS=2
```

```bash
./.venv/Scripts/jupyter.exe nbconvert --to notebook --execute notebooks/smoketest.ipynb --output smoketest_executed.ipynb --ExecutePreprocessor.timeout=1200
```

- Expect in `output/smoketest/<timestamp>/`: `best.pth`, `config.json`, `history.csv`, `training_curves.png`,
  `summary.json`, `test_metrics.json`, `test_predictions.csv`, `top_confusions.csv`, `confusion_matrix.png`,
  `misclassified.png`.
- Then remove `notebooks/smoketest*.ipynb` and `output/smoketest/`. The accuracy numbers mean nothing at this size.
- When printing notebook outputs from Python in this console, set `PYTHONIOENCODING=utf-8`; tqdm characters
  break the default cp1252 encoding.
- Model names must start with a letter or digit (`_smoketest` is rejected).

### Compare runs

Read `output/*/*/summary.json`: `best_val_acc`, `test_accuracy`, `test_balanced_accuracy`, `test_macro_f1`,
`best_epoch`, `minutes`. Per-class detail is in `test_metrics.json`. Prefer balanced accuracy and macro F1 when
comparing, since butterfly dominates the test split (2,756 of 5,129 images).

### Produce the hidden-test predictions

```python
import imgcls
imgcls.predict_folder("output/<model>/<timestamp>/best.pth", r"<hidden test folder>", out_csv="predictions.csv")
```

The output has one row per image and the columns `filename, predicted_category`, using the briefing's names from
`DISPLAY_NAMES` in `imgcls/config.py`. Check the row count equals the number of images in the folder.

### Run or test the API

- Start from the project root: `./.venv/Scripts/uvicorn.exe api.main:app --env-file api/.env`
  (`api/.env` is git-ignored; copy it from `api/.env.example`). Web page: `http://127.0.0.1:8000/`;
  docs page: `http://127.0.0.1:8000/docs`.
- Two endpoints: `POST /predict` (image classifier) and `POST /detect-video` (ready-made open-vocabulary
  detector, `imgcls/detect.py`; the user asked for it). Don't add more unless the user asks. The web page at `/`
  (`api/static/index.html`, tabs Images / Video, no external dependencies) is excluded from the schema.
- The detector is loaded on the first `/detect-video` request, not at startup, so `/predict` works without
  `transformers` / `opencv-python-headless`. Its files live in `model_cache/` (git-ignored, on D:) because C: is
  nearly full; `IMGCLS_DETECTOR_CACHE` overrides. Only OWLv2 / OWL-ViT models are supported.
- `/detect-video` is slow on this CPU (seconds per frame): test with short clips at 1–2 fps, in the background.
- `.claude/launch.json` has an `api` configuration for the desktop app's browser preview (port 8000).
- To test without blocking the shell, start `uvicorn.Server` in a thread (or the CLI via `subprocess`) from a
  Python script in the scratchpad, poll until it is up, post images from `data/<class>/test/` with `httpx`, and
  shut it down. Check the modes (checkpoint; no checkpoint with an ImageNet model; no checkpoint with a CLIP backbone = zero-shot) and a non-image upload (expect 400).
  For video, build a short clip with a known answer from test photos (OpenCV `VideoWriter`, `VP80` in `.webm`
  plays in browsers; this OpenCV build can't write H.264) and check the time ranges.

### Help with the report

- Accuracy: the chosen run's `test_metrics.json`.
- Failure cases: `top_confusions.csv` (counts), `misclassified.png` (examples), `confusion_matrix.png`.
- Method and "what didn't work": README sections "What happens during training", "How the dataset was built"

### Add images to an existing class (only if the user asks)

`apply_screening.py --apply` can't be used (rule 2). Instead:

1. Put the new images in a fresh staging folder, e.g. `new_data/<class>/`.
2. Score them: `./.venv/Scripts/python.exe scripts/screen_images.py --only <class>`. This scores
   `raw_data/<class>` and `new_data/<class>` (whichever exist), skips files already scored, and appends to
   `manifests/clip_scores.csv`.
3. Review with `./.venv/Scripts/python.exe scripts/apply_screening.py --report <scratch dir>` and look at the
   contact sheets. The report also counts older rows of that class whose files no longer exist, so judge only the
   new files' rows.
4. Copy the accepted images into `data/<class>/train` and `data/<class>/test` (70/30, seed 42).
   Check perceptual-hash duplicates against **all** existing images of that class, in both splits, so no photo
   lands in both train and test.
5. Show the user the counts before and after, and only then delete the staging folder.

### Add a new class

Out of scope unless the user asks: the team's class list is fixed by the briefing. If asked anyway, add it to
`DISPLAY_NAMES` in `imgcls/config.py`, collect and screen its images as above, and note that every existing
checkpoint becomes incompatible (class count changes).

## Checkpoint format (`best.pth`)

A dict saved with `torch.save`, loadable with `weights_only=True`:
`model_state`, `arch` (timm name), `classes` (sorted folder names), `img_size`, `mean`, `std`, `epoch`,
`val_acc`, `config` (the notebook settings). `imgcls.load_checkpoint` rebuilds the model from `arch` and
`len(classes)`. Keep this format backward compatible so old runs stay loadable.

## Working style the user expects

- The user wants deliverables done, not described: build it, test it, report what was verified and what wasn't.
- Spot-check automated data decisions visually (contact sheets of what a rule removes and what it barely keeps)
  before applying them, and report counts per class.
- Ask before anything irreversible (deleting data, overwriting edited notebooks, large downloads), and say exactly
  what will be lost.
